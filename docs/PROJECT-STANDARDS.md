# WatchIntervals 项目标准

## 1. 数据与合同

- 手表、手机、云端和 MCP 共享同一计划/训练/睡眠合同。
- 原始轨迹、坐标和逐采样心率不进入普通 MCP 响应。
- 设备控制必须具备 requestId、commandId、期望状态、revision 和过期时间。
- 云端命令已入队不等于手表已经执行，必须返回 pending/acknowledged/completed 的真实状态。
- 云端 MCP 是正式入口；Windows MCP 只作为迁移与本地诊断兼容。

## 2. 界面架构

- 手机端使用 Compose + MVI：状态收敛为单一 `PhoneUiState` 并由 `PhoneViewModel` 持有，页面只负责渲染与发出意图。`MainActivity` 只处理生命周期、系统栏、权限与跨 Activity 跳转。
- 手表端继续使用 View 体系，但所有色值、字号、间距与圆角必须来自 `WatchTokens`，页面不得内联裸色值。
- 双端不得出现巨型单体界面文件；界面构建与业务编排必须分离，页面层不得直接发网络请求或读写存储。
- 所有网络与磁盘访问在单并发作用域内串行执行，状态更新回到主线程。
- 手表 `WorkoutService` 是活动训练状态的唯一权威；手机只读取快照并发送命令。

## 3. 设计令牌与图标

- 颜色、字号、间距、圆角与形状集中在令牌文件，页面只引用语义名，不得内联数值。
- 操作层级必须明确：同一屏内只允许一个主操作；危险操作必须有文字标签，不能只靠颜色传达语义。
- 容器层级分内容层与浮动功能层；玻璃功能层只用于底部导航与连接设置，内容卡不得复用。
- 图标必须是原创矢量几何，不使用 Unicode 字形、平台字体图标或第三方符号库。
- 启动器自适应前景层、单色层与传统层共用同一几何，仅颜色与描边不同；传统层按等比缩放，保证三种呈现完全一致。
- 同一语义色在不同页面必须来自同一令牌，保证跨页面光学重量一致。

## 4. 可访问性

- 交互元素触控目标不低于 48dp，次级紧凑控件不低于 44dp。
- 朗读描述集中在无 Android 依赖的契约对象（`PhoneUiContract`），界面调用契约，测试直接断言契约输出。
- 动态列表操作的描述必须携带位置与当前值，例如“修改第3阶段类型，当前跑步”。
- 测试不得读取界面源码文本断言尺寸或文案，必须验证运行时行为或契约输出。
- 颜色只用于辅助扫读，语义必须同时由文字承载。

## 5. 数据真实性

- 系统未提供的指标显示 `--` 或未知，不得用 0 或估算值补齐。
- 图表不得把缺失数据补成连续色块；多 session 空档与厂商未知阶段按原样保留并说明。
- 刷新失败时保留已有缓存内容并标注原因，不得用空白错误页替换内容。
- 原始字段与聚合字段不一致时按原值分别展示，并说明差异，不做静默归一化。

## 6. 工程与验证

- 关键路径修改必须有防复发测试；无法自动化时写明人工用例编号。
- 双模块构建、Lint 与 JVM 测试是提交前的最小门禁。
- 仓库路径含非 ASCII 字符时单元测试无法加载（BUG-062），需在纯 ASCII 路径的 git 工作树中执行测试；编译与打包不受影响。
- 敏感数据不得进入日志：配对码、token、经纬度与诊断正文均禁止记录。
